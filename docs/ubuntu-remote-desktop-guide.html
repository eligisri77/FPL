Setup guide

Ubuntu Remote Desktop from Windows

Install SSH + xrdp + XFCE so you can open the Ubuntu GUI from Windows Remote Desktop (mstsc). Includes the fixes that prevent the common black screen.

1. What you get

  • SSH — terminal access from Windows PowerShell
  • xrdp + XFCE — full GUI via Windows Remote Desktop
Target: Ubuntu 22.04 (Jammy). Same steps usually work on nearby Ubuntu LTS releases.

2. Install SSH

On the Ubuntu machine:

sudo apt update
sudo apt install -y openssh-server
sudo systemctl enable --now ssh
Use --now with two dashes. -now (one dash) causes: Failed to parse lines 'ow'.

Find the IP:

hostname -I

From Windows PowerShell:

ssh youruser@IP_OR_HOSTNAME
ping IP_OR_HOSTNAME
Test-NetConnection IP_OR_HOSTNAME -Port 22

3. Install remote desktop packages

sudo apt update
sudo apt install -y xrdp xorgxrdp xfce4 xfce4-goodies dbus-x11
sudo systemctl enable --now xrdp xrdp-sesman

If UFW firewall is enabled:

sudo ufw allow 22/tcp
sudo ufw allow 3389/tcp
sudo ufw reload

Verify:

sudo systemctl status xrdp xrdp-sesman --no-pager
sudo ss -lntp | grep 3389
If xrdp fails with Could not start log / error opening log file: 
sudo touch /var/log/xrdp.log /var/log/xrdp-sesman.log
sudo chown xrdp:adm /var/log/xrdp.log /var/log/xrdp-sesman.log
sudo chmod 640 /var/log/xrdp.log /var/log/xrdp-sesman.log
sudo systemctl restart xrdp xrdp-sesman

4. Fix session startup (required on Ubuntu 22.04)

Edit the xrdp startup script:

sudo nano /etc/xrdp/startwm.sh

At the end of the file, use exactly:

unset DBUS_SESSION_BUS_ADDRESS
unset XDG_RUNTIME_DIR
exec startxfce4
Do not keep export $(dbus-launch) above those lines — it conflicts with the unset and can cause a black desktop.
Do not paste terminal commands (like cat > ~/.xsession) into this file.

Create the user session file (run in the terminal, not inside startwm.sh):

cat > ~/.xsession << 'EOF'
#!/bin/sh
unset DBUS_SESSION_BUS_ADDRESS
unset XDG_RUNTIME_DIR
exec startxfce4
EOF
chmod +x ~/.xsession
sudo systemctl restart xrdp xrdp-sesman

Confirm the end of startwm.sh:

tail -8 /etc/xrdp/startwm.sh

5. Fix invisible login / black screen

A pure black RDP window often means the login form is drawn with invisible colors (white text set to black). You never actually logged in — so no desktop starts.

Edit colors:

sudo nano /etc/xrdp/xrdp.ini

In the [Globals] section, set:

black=000000
grey=c0c0c0
dark_grey=808080
blue=08246b
dark_blue=08246b
white=ffffff
red=ff0000
green=00ff00
background=003399

Restart:

sudo systemctl restart xrdp xrdp-sesman
Temporary workaround on a black login screen: click the window → Tab → type username → Tab → password → Enter.

6. Connect from Windows

  1. Open Remote Desktop Connection (mstsc)
  2. Computer: Ubuntu IP from hostname -I
  3. Connect
  4. On the xrdp login screen:
    • Session: Xorg
    • Username: your Ubuntu user
    • Password: your Ubuntu password
  5. Click OK — XFCE desktop should appear
Prefer leaving Ubuntu at the login screen (not signed into a local GUI session with the same user). Same-user local + RDP often conflicts.

7. Before connecting checklist

  • PC is powered on (not asleep / hibernated)
  • BitLocker / disk encryption unlocked once physically after reboot
  • Network reachable: ping works from Windows
  • ssh and xrdp services are active
  • Port 3389 listening
  • startwm.sh ends with unset + exec startxfce4
  • xrdp.ini has visible colors (white=ffffff)

9. Troubleshooting

Problem Cause Fix
Failed to parse lines 'ow' Used -now instead of --now sudo systemctl enable --now ssh
SSH / RDP timeout Wrong network, PC asleep, firewall Ping first; wake PC; check UFW; use correct IP
Destination host unreachable Different subnet / routing Same VLAN/VPN; confirm IP with hostname -I
Black RDP, no desktop Invisible login colors; never logged in Fix xrdp.ini colors; Tab + type credentials
Black after login Bad startwm.sh / GNOME conflict XFCE + unset lines + exec startxfce4; log out local GUI
xrdp log file error Bad ownership on log files chown xrdp:adm /var/log/xrdp*.log

Useful diagnostics

who
sudo systemctl status xrdp xrdp-sesman --no-pager
sudo tail -80 /var/log/xrdp.log
sudo tail -80 /var/log/xrdp-sesman.log
ls -la ~/.xorgxrdp-*.log ~/.xsession-errors 2>/dev/null
tail -8 /etc/xrdp/startwm.sh
cat ~/.xsession
If /var/log/xrdp.log shows draw login window then disconnect, and there is no ~/.xorgxrdp-*.log, you never completed login.

10. BitLocker / disk encryption

After a full reboot, encryption unlock (BitLocker PIN / recovery / LUKS passphrase) must be entered physically. You cannot skip this remotely over SSH.

  • Avoid remote reboots when possible — restart services instead: 
    sudo systemctl restart xrdp xrdp-sesman
  • After unlock once, leave the PC on (login screen is fine)
  • Ask IT about BitLocker Network Unlock if remote reboots are required often
